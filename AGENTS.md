- Catalog rows in public_jobs are never hard-deleted: liveness sets is_active=false (only on HTTP 404/410) and every reader/stat view filters is_active=true — keeps history and avoids false deletions from flaky portals.
- Liveness sweep is self-driving: pg_cron calls check-job-liveness every 5 min with a DB lease, adaptive batch size and per-source 429 backoff stored in liveness_* tables; rows re-checked after 3 days — keeps the catalog fresh without manual runs.
- Employer accounts: role comes only from user_roles ('employer' via signup metadata user_type, everything else 'user'); companies are read publicly only through the public_companies view (active rows, no user_id) — base table stays owner/admin-only.
- Company logos live in the private company-logos bucket; public-company-logo signs only logos referenced by active companies server-side, while owners sign their own draft logos directly to keep unpublished files private.
- AccountRouteGuard validates Auth and protected user_roles before mounting account pages; role lookup errors fail closed to prevent onboarding redirects for employers.
- Employer offers live in employer_jobs; DB triggers (not UI) enforce status rights (employers: draft/pending_review/closed only), sync published offers into public_jobs (source_portal='employer', company_id, url '/company/:slug?job=id') and deactivate that copy on close/draft/expiry/delete — one source of truth for permissions.
- Background catalog jobs (liveness, archiles-enrich, categorize, translations) skip rows with company_id / source_portal='employer' so employer-authored data is never overwritten; matching falls back to regex skill classification for them.

- Employer review: protected columns (approval, trust, reports, rejection notes, suspension) are reverted for non-admins in BEFORE triggers via is_privileged_writer(); internal trigger writes set the transaction-local app.leslie_privileged flag — UI never enforces rights.
- An employer offer can go live only when its company is active AND approved_at is set (DB-enforced); public_companies shows only approved companies, owners preview their own via the base table.
- Employer contact: contact emails never go into public_jobs/raw_data (only contact_options); emails are served via the authenticated get_employer_job_contact_email RPC, which logs reveals to employer_job_email_reveals (not applications). job_applications (methods cv/message) are validated and filled (applicant identity, email, CV snapshot) by a BEFORE INSERT trigger, and a weekly cron deletes them 6 months after employer_jobs.closed_at — client input is never trusted for identity.
